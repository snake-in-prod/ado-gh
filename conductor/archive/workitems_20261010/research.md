**2. Process differences** (docs as of 2026)
- Categories: `Microsoft.RequirementCategory`, `BugCategory`, `TaskCategory`, `FeatureCategory`, `HiddenCategory` (test plan/suite, shared steps, code review, feedback), plus test categories. `Microsoft.EpicCategory` is not in the sample (14 categories): confirm live.
- Requirement category default: User Story (Agile), Product Backlog Item (Scrum), Issue (Basic), Requirement (CMMI). It can hold several types; use `defaultWorkItemType` for the alias and accept any member.
- Basic has no Bug type ("it tracks bugs as Issues"); whether `BugCategory` exists there is undocumented (o3).

| Process | Proposed | In Progress | Resolved | Completed | Removed |
|---|---|---|---|---|---|
| Agile | New | Active | Resolved (Bug in the table) | Closed | Removed (Epic, Feature, User Story; Task not covered) |
| Scrum | New, Approved; To Do (Task) | Committed; Open (Impediment) | none | Done | Removed |
| Basic | To Do | Doing | none | Done | none |
| CMMI | Proposed | Active, plus Resolved for Epic/Feature/Requirement/Task | Resolved (Bug, Issue, Review, Risk) | Closed | none by default |

Rules: only one Completed state per type, so "first Completed" is *the* Completed state. The first Proposed state is the default for new items. A workflow needs a Proposed **or** In Progress state, and some types have no Proposed state (Agile Issue `"" → Active`, Scrum Impediment Open/Closed), so reopen falls back to the first In Progress state. Inherited states can't be renamed or recategorised, only hidden; custom states go in Proposed/In Progress/Resolved/Completed (max 32 per type); whether a custom state can go in Removed is only documented for CMMI, confirm live. Adding a custom Completed state hides the inherited one.

Consequences: close → Closed (Agile, CMMI) / Done (Scrum, Basic). `--resolve` works only for Agile Bug (and what the table omits) and CMMI Bug/Issue/Review/Risk; a CMMI Requirement's "Resolved" is In Progress (o4). `--removed` fails on Basic, CMMI and Agile Bug. Resolver order: exact type name case-insensitive → alias via category default → alias as type name → error; exclude disabled and Hidden-category types.

## Phase 1: Work Item Foundation — WIQL builder

### q4. WIQL rules: string literal escaping (single quotes), escaping in tags and area/iteration paths, injection risks, `UNDER`, `CONTAINS WORDS` vs `CONTAINS` for System.Tags, `@Me`, `@Today`, `@CurrentIteration` with team context (and the `[Any]` team form), `@TeamAreas`, ORDER BY System.ChangedDate, `$top`, the 20,000 result cap (VS402337), WIQL length limit (32K). Work item batch get (workitemsbatch): 200 id limit, `errorPolicy=omit`, field list, `$expand=relations` incompatibility with fields.
**Answer:**
**1. String literals (high).** Strings are `'...'` or `"..."`; the only escape is doubling the quote (`''`), no backslash escape (official grammar `<string> ::= ''' { <anychar except '''> | '''' }* '''`; wiql-editor tokenizer `/'(?:[^']|'')*'/`). Always emit single-quoted values via `strings.ReplaceAll(v, "'", "''")` for titles, states, types, tags, identities and paths. Backslashes in paths are literal; JSON escaping is done by `json.Marshal`. Injection protection: (a) every user value quote-doubled, (b) numbers (IDs, priority, `-S` IDs) formatted from Go ints, (c) field names never from user text: only resolved reference names checked against `^[A-Za-z0-9_.]+$` go in `[...]` (no escape for `]`), (d) macros only as fixed tokens. Test `O'Brien`, `x' OR [System.Id] > 0 OR 'a'='a`, `]`, a backslash and `@Me` as literals.

**2. Paths (high).** TreePath operators: =, <>, In, Not In, Under, Not Under; `UNDER` matches the node and descendants. Emit `[System.AreaPath] UNDER '<escaped>'` after validating against classification nodes.

**3. Tags (medium-high).** Tags support only Contains / Does Not Contain; Contains Words is for full-text indexed long-text fields (100-char limit). `Tags Contains` uses the tag index; treat it as whole-tag (substring behaviour unconfirmed: live check). "All must match" → one `[System.Tags] CONTAINS 'x'` clause per tag joined with AND. Tags can't contain `,` or `;`, max 400 chars; tags starting with `@` can't be queried; keep under 25 tag clauses.

**4. Macros.**
- `@Me` on identity fields (medium: Microsoft's 2026 ai-assisted query-operators page claims "@CurrentIteration, @Me, @Follows, and @TeamAreas work only in the web portal"; real-world REST usage contradicts it; live check). Unassigned: `[System.AssignedTo] = ''`.
- `@Today` with integer offset (high).
- Always add `[System.TeamProject] = @project`; the URL project only sets macro context (medium).
- `@CurrentIteration('[Project]\Team')` with optional `<...>` suffix (the editor's regex `( <.*>)?` accepts any text in angle brackets) and +/- n offset; REST takes the team in the route (`QueryByWiqlArgs.Team`); the WIQL syntax page's REST section shows `@CurrentIteration('[Contoso]\\Web')`. Recommendation: the builder resolves `@current` via `GetTeamIterations($timeframe=current)` to a concrete path and emits `UNDER '<path>'` (same resolver serves `create --iteration @current`); only `ado wi query` passes the macro through with the team set (o10).
- `@TeamAreas` only on Area Path (`=` per docs; `IN (@TeamAreas(...))` seen in the wild); pass-through only.
- `[Any]` is a documented macro (`Work Item Type = [Any]`); no team form exists. The builder simply omits the clause.

**5. ORDER BY (high).** `ORDER BY [System.ChangedDate] DESC, [System.Id] DESC` (Id as tie-breaker, suggestion). ORDER BY/ASOF aren't allowed in tree queries.

**6. Limits.** Always send `$top` (`-L` for list, 200 default for query). 20,000 cap: the limits page says results are silently truncated; a Q&A thread reports REST failing with VS402337 even with `$top=1000`, so whether `$top` avoids the error is unknown (low). Handle both: map VS402337 to "narrow filters / use -L", and note truncation. WIQL ≤ 32,000 chars (high): check `len(wiql)`; only the `-S` `ID IN (...)` list can grow, so chunk or cap it (o11).

**7. Batch fetch.** `POST {org}/{project}/_apis/wit/workitemsbatch` `{ids, fields, $expand, asOf, errorPolicy}`, max 200 IDs (high); SDK pins 7.1-preview.1. Chunk at 200 and restore WIQL order. `errorPolicy` Fail/Omit: with Omit, deleted/inaccessible IDs come back as null entries (medium: indirect evidence from Microsoft's Retrospectives extension using `getWorkItems` with Omit); the SDK decodes null into a WorkItem with nil Id, so skip those. Identity fields come back as objects. Never send `fields` together with `$expand` (Microsoft's MCP: "For get, cannot be combined with fields"; Qwiq clears fields with expand=All): list uses fields, view/relations use `$expand=relations` without fields.

**8. Reuse.** No WIQL code exists in the repo; the SDK provides `GetWorkItemsBatch`, `QueryByWiql` (Team, Top), `WorkItemErrorPolicyValues.Omit`, `GetTeamIterations` (Timeframe). No new dependency.

### q5. ### q9. Saved queries REST 7.1: get by path vs by id (`/_apis/wit/queries/{path}` with `$expand=wiql|all`, `$depth`), query folders tree (My Queries / Shared Queries), running a saved query (`/_apis/wit/wiql/{id}` with team in route), team-scoped WIQL endpoint (`{project}/{team}/_apis/wit/wiql`), result shapes for flat (`workItems`), tree and one-hop (`workItemRelations` with source/target/rel), `columns` mapping to fields, `$top`, and `timePrecision`.
**Answer:** SDK v7.1.0 `workitemtracking` covers every Phase 5 endpoint (7.1-preview.x); no raw REST.

1. **Get by path or id**: `GetQuery(Project, Query, Expand, Depth, IncludeDeleted, UseIsoDateFormat)` → `GET {project}/_apis/wit/queries/{query}`, "ID or path of the query". The SDK `url.PathEscape`s the path as one segment (`Shared%20Queries%2FTeam%2FActive%20Bugs`), as the Node SDK and Microsoft's MCP do; server acceptance of `%2F` is inferred, not live-tested. Use `$expand=wiql` (columns + WIQL; values none/wiql/clauses/all/minimal). Response `QueryHierarchyItem`: id, name, path, isFolder, hasChildren, isPublic, queryType (flat/tree/oneHop), columns, wiql, `_links.html` (`web/qr.aspx?pguid=…&qid=…`, usable for `-w`). A folder → "not a query".
2. **Folder tree**: `GetQueries(Project, Expand, Depth, IncludeDeleted)` → roots "My Queries" and "Shared Queries" with `children` to the requested depth; deeper folders have `hasChildren: true` and no `children`. The TFS-era docs cap `$depth` at 2; the 7.1 docs state no maximum. 3. **Run saved query**: `QueryById(Id, Project, Team, TimePrecision, Top)` → `GET {project}/{team}/_apis/wit/wiql/{id}`; project and team optional route values (dropped when empty). Pass the FR1 team for `@CurrentIteration`/`@TeamAreas`. Path input = `GetQuery(path)` then `QueryById(id)`.
4. **Ad-hoc WIQL**: `QueryByWiql(Wiql{Query}, Project, Team, TimePrecision, Top)` → `POST {project}/{team}/_apis/wit/wiql`; ≤ 32,000 chars.
5. **Result shape** (`WorkItemQueryResult`): `queryType`, `queryResultType` (workItem/workItemLink), `asOf`, `columns []{referenceName, name, url}`, `sortColumns`, and either `workItems []{id, url}` (flat) or `workItemRelations []{rel, source, target}` (tree/one-hop). Headers use `columns[].name`; JSON keys are o21.

7. **`timePrecision`**: bool, "Whether or not to use time precision"; leave unset (YAGNI).
8. **`-w`**: only official link is `_links.html` (`{org}/web/qr.aspx?pguid={projectId}&qid={id}`); inline WIQL has no saved query, matching the spec's saved-queries-only rule.

**1. Rate limits (TSTUs).** 200 TSTUs per user in any sliding 5-minute window. Under load Azure DevOps first delays requests (up to 30 s), still answering 200 with `Retry-After`; only when blocking does it answer 429 (TF400733). "Complex work item queries" are a named heavy operation.
- **Already handled**: the shared transport reads `Retry-After` on any response, retries a 429 up to 3 times, caps the wait at 1 min, and slows down on `X-RateLimit-Remaining: 0` (api/http_client.go:71-193, api/throttle_test.go). Route every new call through it; no new throttling code.
- **Keep call counts small**: `list` = 1 WIQL + one batch per 200; `view` fetches linked items in one batch; `sprint`/`board` a fixed handful; cap parallel calls with errgroup like `pr diff` (apidiff.go:82).
