**Answer:**

Keep ado's own IOStreams struct, parse `ADO_FORCE_TTY` itself, get width from `golang.org/x/term.GetSize` (already a go-gh dependency).

## Phase 2: Context Detection — Remote URL parser

### q9. Azure DevOps git remote URL formats and edge cases a parser must handle
**Answer:** New code in `internal/adocontext`; grammar based on dotnet/sourcelink `AzureDevOpsUrlParser`, azure-devops-cli-extension `uri.py`, azure-repos-vscode and Microsoft Learn.

**Forms to accept**
1. `https://[user[:secret]@]dev.azure.com/{org}/{project}/_git/{repo}` — the clone dialog puts the org in the username. Ignoring userinfo is a design choice: az devops instead rejects `user:secret@`, rejects a username ≠ org on dev.azure.com and any userinfo on visualstudio.com. Never log or echo the raw remote (may contain a PAT).
2. `https://{org}.visualstudio.com/[DefaultCollection/]{project}/_git/{repo}` — org from the first host label; strip `DefaultCollection` case-insensitively. SourceLink also accepts a team segment here (`/{project}/{team}/_git/{repo}`; drop the team).
3. Project omitted: `dev.azure.com/{org}/_git/{repo}` and `{org}.visualstudio.com/[DefaultCollection/]_git/{repo}` → project = repo (SourceLink `projectPath = projectName ?? repositoryName`; az devops does not accept it on dev.azure.com).
4. Limited-refs segments `_git/_full/{repo}` and `_git/_optimized/{repo}` → drop the segment; the same may appear in SSH v3 before `{repo}`.
5. SSH v3 scp-style `git@ssh.dev.azure.com:v3/{org}/{project}/{repo}` (current format).
6. Old host `{org}@vs-ssh.visualstudio.com:v3/{org}/{project}/{repo}` (still works) — take the org from the path, never the username.
7. `ssh://git@ssh.dev.azure.com[:22]/v3/{org}/{project}/{repo}` (and vs-ssh).
8. SSH v3 with a team segment `v3/{org}/{project}/{team}/[_full|_optimized/]{repo}`: SourceLink accepts (project/team), az rejects. Pick one rule (take project, drop team — or reject) and test it. SSH v3 without a project (`v3/org/repo`) is rejected by SourceLink, so "project omitted" does not apply to SSH.
9. Legacy v1/v2 SSH `ssh://{org}@vs-ssh.visualstudio.com[:22]/{project}/_ssh/{repo}`: az devops accepts only the 3-segment `{project}/_ssh/{repo}` (org from the SSH username) and a `{org}/{project}/_ssh/{repo}` form; a `DefaultCollection/` prefix makes az read org=`DefaultCollection` and reject. SourceLink flags all v1/v2 as unsupported. Optional.
10. SSH host aliases (`git@devops_fabrikam:v3/Fabrikam/Project1/fab_repo`) are documented by Microsoft for multi-org keys; go-gh `pkg/ssh` Translator resolves via `ssh -G`.

**Decoding and validation**
- Repo/project names "must not start with an underscore", so `_git`, `_ssh`, `_full`, `_optimized` are positional markers — true for UI-created names; the docs warn the API can create names with UI-restricted characters. Projects also reserve `App_*`, `bin`, `web.config`.
- Forbidden in both: `\ / : * ? " < > ; # $ { } , + = [ ] |`; projects also forbid `'`. Spaces, `%`, `&`, `( )`, `@`, `!`, `~`, Unicode allowed; max 64 chars. Org names: English letters, digits, hyphens.
- Split `u.EscapedPath()` on `/`, `url.PathUnescape` once per segment (`%20`→space, `%25`→`%`; so `%2F` can't fake a segment). Never QueryUnescape, never decode twice; re-escape with `url.PathEscape` when building URLs.
- Case: az devops compares host, `_git`, `v3`, `_ssh` case-insensitively; SourceLink only `DefaultCollection`. Case-insensitive is the safer choice.
- Tolerate a trailing slash. Keep a `.git` suffix (ADO reads `repo.git` literally, TF401019 — user report, not docs).
- Reject: lookalike hosts (`dev.azure.com.evil.com`, `notvisualstudio.com`), `vs-ssh.visualstudio.com` as HTTPS host, empty segments, control chars/backslash, ports other than 443/22, a team segment on dev.azure.com.

**Go note:** `url.Parse` can't read scp-style remotes; copy go-gh's ~10-line pattern (no scheme, contains `:`, no `\` → `"ssh://" + strings.Replace(raw, ":", "/", 1)`); go-gh's ParseURL is internal.

**Server fallback (not MVP):** `GET {remoteUrl}/vsts/info` returns `repository.project.name` (used by az and azure-repos-vscode); no helper in the Go SDK, would need raw net/http.

## Phase 3: Authentication — Credential store

### q3. zalando/go-keyring on WSL and Linux without Secret Service / D-Bus: errors, detecting "no keychain", size limits, fallbacks, and how gh does keyring-with-plaintext-fallback
**Answer:** Based on go-keyring v0.2.8 (latest, 2026-03-23, the version gh pins), godbus/dbus v5.2.2, cli/cli trunk.
1. **Errors.** Sentinels: `ErrNotFound`, `ErrSetDataTooBig` (keyring.go) and `ErrUnsupportedPlatform` (keyring_fallback.go, non-Linux/BSD only). On Linux each call opens `dbus.SessionBus()` and passes errors through unwrapped — there is no "unavailable" sentinel:
   - **No session bus** (containers, CI, plain WSL, SSH): godbus tries `DBUS_SESSION_BUS_ADDRESS`, `/run/user/<uid>/bus`, then autolaunches `dbus-launch`; missing → `exec: "dbus-launch": executable file not found`; present → starts a stray bus as a side effect. Or `dbus: couldn't determine address of session bus`.
   - **Bus but no keyring daemon** (WSL2 with systemd): `org.freedesktop.DBus.Error.ServiceUnknown` — "The name org.freedesktop.secrets was not provided by any .service files".
   - **Locked collection**: go-keyring calls Unlock and blocks on the prompt's `Completed` signal with no timeout or context, so it **can block indefinitely** if the daemon never signals; if the prompt is dismissed or fails, Unlock returns "failed to unlock correct collection".
   - **`login` collection missing**: falls back to the `aliases/default` collection; fails only if that is also missing or can't be unlocked.
2. **Detection.** Don't probe or string-match. Like gh: run Set/Get/Delete in a goroutine with a timeout (gh: 60 s, `*TimeoutError`). Any Set error (incl. `ErrSetDataTooBig`, timeout) → fall back. On Get, `ErrNotFound` = nothing stored, other error = unusable; both continue to the config-file source. Tests: `keyring.MockInit()` and `keyring.MockInitWithError(err)`.
3. **Size limits** (enforced in code): Windows password ≤ 2560 bytes and service name < 512 bytes (the keyring.go comment says 32 KiB, the code says 512); macOS whole `security -i` command ≤ 4096 bytes after base64 (~3000 raw bytes for service+user+secret); Linux no limit (slow > ~100 KiB). A PAT (52–84 chars) fits everywhere; an MSAL cache very likely does not fit on Windows/macOS (inference, not measured).
4. **gh** (`internal/config/config.go` `AuthConfig.Login`): if secure storage (default since v2.26.0, April 2023) → `keyring.Set("gh:"+host, user, token)`, and on success remove plaintext `oauth_token` under `hosts.<host>.users.<user>`. If `--insecure-storage` or Set failed → write `oauth_token` to hosts.yml, return `insecureStorageUsed=true`, print `! Authentication credentials saved in plain text` to stderr. File 0600, dir 0771 (go-gh `pkg/config`). Read order: env → config `oauth_token` → keyring; `gh auth status` reports the source.
5. **Fallbacks.** (a) 0600 plaintext + stderr warning, gh-style — simplest, matches the spec. (b) Windows Credential Manager from WSL: go-keyring has no WSL path; only bridge is calling a Windows exe via interop (as GCM does) — fragile; skip, document `ADO_TOKEN` + plaintext fallback. (c) Encrypted file with key in a keyring (azidentity/cache uses kernel keyctl + `$XDG_CACHE_HOME`) — relevant for the MSAL cache, not the PAT.

## Phase 3: Authentication — Authenticated HTTP transport

### q5. azure-devops-go-api v7 Connection internals: custom http.Client/RoundTripper, Bearer and refresh, User-Agent, logging; maintenance status; how other Go tools share auth
**Answer:** No supported way to give typed clients a custom transport through `Connection`; auth is a static string; no logging hooks; User-Agent can only be appended. Workaround is small. (Checked at tag `azuredevops/v7.1.0` and dev; client.go, connection.go, client_options.go identical.)
1. **Transport.** `Connection` exposes AuthorizationString, BaseUrl, UserAgent, SuppressFedAuthRedirect, ForceMsaPassThrough, Timeout, TlsConfig; caches unexported. `git.NewClient(ctx, conn)` → `GetClientByResourceAreaId` → `GetClientByUrl` → `NewClient(conn, url)` builds a bare `&http.Client{}`; the ResourceAreas lookup also runs on a default client. `azuredevops.WithHTTPClient(hc)` exists only for `NewClientWithOptions`. Every typed package exports `ClientImpl{Client azuredevops.Client}`, so: `&git.ClientImpl{Client: *azuredevops.NewClientWithOptions(conn, orgURL, azuredevops.WithHTTPClient(shared))}` (same for core, workitemtracking, build; `pipelines.NewClient` uses BaseUrl already). The OPTIONS `_apis` discovery then also uses the shared transport. This skips the resource-area lookup: fine on-prem; on dev.azure.com/*.visualstudio.com git/core/wit/build/pipelines are believed to live under the org URL (unconfirmed live). If needed, `(*azuredevops.Client).GetResourceAreas(ctx)` is exported and can run through the shared client. Upstream PR #122 (custom HTTP client) open since 2022-09.
2. **Auth.** `AuthorizationString` is copied into unexported `client.authorization` at creation and added verbatim per request only when non-empty; no callback; cached clients stored by value. Bearer = `"Bearer " + token` (no helper, PR #187 open); no refresh (PR #194 `AuthProvider` open). Design: leave AuthorizationString empty and set Authorization in our RoundTripper from the token provider (Basic for PAT, Bearer for Entra, refresh) — shared with the raw client, no duplicate headers.
3. **User-Agent.** Base `go/<ver> (<os> <arch>) azure-devops-go-api/7.1.220.1 (dev)` plus appended `Connection.UserAgent`; full replacement only in the RoundTripper.
4. **Logging/retry.** `SendRequest` is `client.client.Do(request)` with "todo: add retry logic"; no Retry-After (issue #102). Redacting debug log lives in the RoundTripper.
5. **Errors.** `UnwrapError` returns `WrappedError` (StatusCode) only for empty (`ContentLength == 0`) or text/plain bodies; HTML bodies and chunked empty bodies (ContentLength -1) go to json.Unmarshal and lose the status. It returns a pointer on some paths and a value on others. Detect 401 in the transport. Keep `SuppressFedAuthRedirect: true` (NewPatConnection sets it).
6. **Maintenance.** Not archived; latest tag v7.1.0 (2023-04-17), earlier v6.0.1 (2022-01), v6.0.0 (2021-12); occasional dev commits (#185 2024-10, #198 2026-06). 54 open issues + 16 open PRs; "is this maintained?" (#190, #197) unanswered.
7. **Others.** terraform-provider-azuredevops `replace`s to magodo's fork (adds `Connection.AuthProvider`, pulls azcore); azd uses `NewPatConnection`; Spacelift forked for the custom client. None share auth with a raw client.

### q2. MSAL Go token cache persistence and refresh; cache size vs keychain limits; silent refresh; browser login vs device code on WSL/headless
**Answer:** Versions: MSAL Go v1.10.1, go-keyring v0.2.8, go-gh v2.16.2 (cli/browser v1.3.0).
1. **Cache contract** (`apps/cache`): `public.WithCache(accessor)` with `Replace(ctx, cache.Unmarshaler, cache.ReplaceHints) error` and `Export(ctx, cache.Marshaler, cache.ExportHints) error`. Nil ctx unsupported; a ctx without deadline must get a default timeout from the implementor; retries live in the implementation. `Replace` runs before cache reads (AcquireTokenSilent, Accounts, AuthResultFromToken, RemoveAccount); `Export` runs after writes (new/refreshed tokens, RemoveAccount) — a silent call returning a cached token writes nothing. PartitionKey can be ignored for public clients. Traps: (a) any Replace/Export error aborts the token call — an Export error discards a successful AuthResult, so a keychain failure would fail a good login; (b) empty/nil bytes are **fine** — `storage.Manager.Unmarshal` uses MSAL's internal json, which returns nil on empty input (skipping Unmarshal when nothing is stored is harmless, not required); (c) data that fails your own decryption → treat as empty cache (return nil, user logs in again); corrupt JSON would still error. Write the file atomically (temp + rename); no locking (last write wins).
2. **Size vs keychain.** go-keyring returns `ErrSetDataTooBig` above 2560 bytes (Windows, = CRED_MAX_CREDENTIAL_BLOB_SIZE) or a 4096-byte `security` command (macOS, ~3000 raw bytes). A serialized cache (AT JWT + RT + ID token + account + metadata) is estimated 5–12 KB — unsourced; confirm with `len(Marshal())` against a real org. Either way "cache persisted in keychain" won't work as one item on Windows/macOS. Microsoft's own tools use DPAPI file (Windows), Keychain via cgo (macOS), libsecret via cgo or keyctl + encrypted file (Linux); the extensions module needs cgo, conflicting with `CGO_ENABLED=0`. Recommendation (stdlib + go-keyring): random 32-byte AES-GCM key stored base64 (~44 bytes) in go-keyring (`ado:<host>` / `msal-cache-key`), cache AES-GCM-encrypted in a 0600 file under the user config/cache dir — one code path, `crypto/aes` + `crypto/cipher`. Chunking across keyring items is worse (partial writes corrupt, chunk bookkeeping, a `/usr/bin/security` process per call on macOS). Keyring unavailable → memory only or plaintext-with-warning (open question); the refresh token is the valuable part if stolen.
3. **Silent refresh.** Save `AuthResult.Account.HomeAccountID` (not secret) in per-host config; on use `client.Accounts(ctx)` → pick by HomeAccountID → `AcquireTokenSilent(ctx, scopes, public.WithSilentAccount(acct))` (no account → `errNoAccount`). MSAL returns a valid cached AT, refreshes early after RefreshOn, else redeems the RT, and Exports. Any error → `AuthError` (exit 4) "run: ado auth login". Logout: `RemoveAccount`, delete cache file and keyring key.
4. **Browser vs device code.** MSAL's interactive flow listens on `localhost:<random port>` and waits on `ctx.Done()` only — pass a Ctrl-C-cancellable ctx with a timeout. WSL2 `localhostForwarding` (default true) or mirrored mode makes the redirect reach the listener. MSAL's default opener (`github.com/pkg/browser`) tries only xdg-open, x-www-browser, www-browser — no wslview. Pass `public.WithOpenURL(...)` backed by go-gh `pkg/browser` with an explicit ado launcher (ADO_BROWSER → BROWSER); go-gh's own resolution reads GH_BROWSER and gh's config, **not** git's `browser` config. Empty launcher → cli/browser, which includes wslview. If openURL errors, AcquireTokenInteractive returns that error, so the CLI writes the device-code fallback (az login does the same). Selection rule: `--device` forces device code; SSH_CONNECTION/SSH_TTY, or Linux outside WSL with no DISPLAY and no WAYLAND_DISPLAY → device code; otherwise interactive with fallback on openURL error. WSL detection via `WSL_DISTRO_NAME`/`WSL_INTEROP` or `/proc/sys/fs/binfmt_misc/WSLInterop` is a common heuristic, not official. xdg-open can exit 0 headless without opening — the DISPLAY check covers it.

### q7. How Azure DevOps REST APIs paginate across areas; what a generic `ado api --paginate` can rely on; merging `value` arrays; how the Go SDK exposes continuation tokens
**Answer:** No single contract.
1. **Per area**
   - **Header → query param (main pattern):** response `X-MS-ContinuationToken`, sent back as `?continuationToken=`; header gone = done; body `{count, value}`. Core projects, Build builds/definitions/changes, Git refs and PR commits, Pipelines list, Graph users/groups (on `vssps.dev.azure.com`: "The only reliable way to know if there is more data left is the presence of a continuation token"). Only the Graph page documents the header; for Core/Build/Git the header is evidenced by the generated SDK and community sources. Projects' token is an int32 "how many projects already been fetched" — still echo it as opaque.
   - **Token in body:** WIT reporting revisions `{values, continuationToken, nextLink, isLastBatch}` (array is `values`; sample carries a token with `isLastBatch: true`, another sample a `nextLink` without token — never loop without the guard). Audit (`auditservice.dev.azure.com`) `{value:{decoratedAuditLogEntries, continuationToken, hasMore}}`, token present while `hasMore` false.

## Phase 5: Pull Request Commands — ado pr checkout

### q11. Pull request refs in Azure DevOps; fetching the source branch for same-repo vs fork PRs; what `ado pr checkout` should fetch and name the branch
**Answer:** Azure Repos documents only `refs/pull/{id}/merge` — the server's preview merge of source into target, not the source tip. No documented `refs/pull/{id}/head` (third-party claims disagree on its path). So checkout fetches the real source branch from REST fields, not a pull ref.
1. **Refs.** `Build.SourceBranch` example "refs/pull/1/merge"; PR builds run on the merge commit. `lastMergeCommit` is empty when the merge is in progress or failed → merge ref may be missing/stale on conflicts. `lastMergeSourceCommit` = source head at last merge; may lag.
2. **Same-repo vs fork.** Fields (REST 7.1, SDK `git.GitPullRequest`): `sourceRefName`, `repository` (target), `forkSource` (`GitForkRef{Name, ObjectId, Repository{RemoteUrl, SshUrl, IsFork}}`, set only for fork PRs).
   - Same-repo: fetch `+refs/heads/<b>:refs/remotes/<remote>/<b> --no-tags` from the remote matching the PR repo, then `checkout -b <local> --track <remote>/<b>` (gh's `cmdsForExistingRemote`).
   - Fork: forks exist only within the same org (same host/credential helper). If a local remote matches `forkSource.repository.remoteUrl`, use the same-repo path. Otherwise fetch by URL `git fetch <forkUrl> <sourceRefName>:<local> --no-tags` and set `branch.<b>.remote`/`pushRemote` = fork URL, `branch.<b>.merge` = sourceRefName. This is an ado adaptation: gh's `cmdsForMissingRemote` always fetches `refs/pull/N/head` from the base repo; MaintainerCanModify only changes the branch config. ADO has no maintainer-can-modify; push rights come from the fork's permissions.
   - Optional fallback when the fork is unreadable: fetch `refs/pull/<id>/merge`, `checkout -b <local> <lastMergeSourceCommit>` (SHA from API, not `merge^2`); warn read-only/stale.
   - `az repos pr checkout` ignores `forkSource` (fetch remote sourceRefName, checkout, pull) — breaks on fork PRs.
3. **Behaviour (gh-like):** local name = `sourceRefName` minus `refs/heads/`; `-b` overrides. When the fork branch equals the default branch on the missing-remote path, prefix (`<forkRepoName>/main`; gh prefixes only on that path). Existing local branch → checkout + `merge --ff-only`; `-f` → `reset --hard`. Already on it → fetch + ff/reset in place. Always `--no-tags`; reject branch names starting with `-`. gh's `--detach`, `--recurse-submodules`, `--worktree` not in spec.

Caveat: whether `forkSource.repository.remoteUrl` is populated is undocumented; else look up the repo by id or build `https://dev.azure.com/{org}/{project}/_git/{name}`.
